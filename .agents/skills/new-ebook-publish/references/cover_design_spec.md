# 표지 디자인 스펙 (단일 진실원)

선비북스 전자책 표지의 품질 기준. 참조 표본: 『LLM Wiki』 (딥 그린 배경 + 레이어드 페이퍼 렌더 + 골드 악센트).
이 스펙은 이미지 생성 프롬프트를 만들 때 그대로 반영한다.

## 1. 서지 텍스트 — _meta.md와 완전 일치 (절대 규칙)

표지에 들어가는 모든 문구는 `_meta.md`가 단일 진실원이다. 임의 창작 금지.

| 표지 요소 | 소스 필드 | 규칙 |
|---|---|---|
| 제목 | `title` | 글자 그대로. 축약·의역 금지 |
| 부제 | `subtitle` | 글자 그대로 |
| 저자 | `author` | 글자 그대로 (예: 정선비) — **불일치 시 ISBN 반려 1순위** |
| 출판사 | `publisher` | 하단에 작게 (선비북스) |
| 시리즈 라벨 | `series` (있을 때만) | 없으면 표지에 시리즈 칩을 넣지 않는다 |
| 태그라인 | `cover_tagline` (있을 때만) | 없으면 생략. **다른 책 문안 재사용 절대 금지** |

생성 후 반드시 표지를 판독해 위 항목을 대조하고 `cover_meta_match_status`를 기록한다 (SKILL 단계 7).

## 2. 레이아웃 (참조 표본 구도)

세로 2:3 (최종 1500×2220px). 위→아래 순서:

1. **시리즈 칩** (선택): 좌상단, 가는 외곽선 라운드 박스 + 소형 텍스트
2. **제목**: 상단 1/3, 초대형 타이포그래피 (캔버스 폭의 80~90%), 크림/아이보리색, 최대 2줄, 세리프 또는 두꺼운 고딕
3. **부제**: 제목 아래, 가는 수평 규칙선 1~2개 사이에 배치, 1~2줄
4. **중앙 일러스트**: 중하단 1/2 영역 — 책의 은유(cover ledger 콘셉트)를 표현한 오브젝트 클러스터
5. **저자·출판사**: 하단, 저자는 중앙 또는 좌측, 출판사는 최하단 소형

## 3. 일러스트 품질 기준 (참조 표본 수준)

- **입체 렌더 질감**: 종이·카드·오브젝트가 부드러운 스튜디오 조명 아래 실제 소재감(종이 결, 미묘한 그림자, 얕은 심도)을 가질 것. 플랫 벡터 단색 도형만으로 끝내지 말 것
- **레이어드 구성**: 오브젝트 2~4개가 겹치거나 계단식으로 배치되어 깊이감 형성
- **악센트 라인·포인트**: 골드/구리 등 금속성 포인트 컬러로 연결선·노드·리본 등 1~2개 디테일
- **금지**: AI 클리셰(글로우·렌즈플레어·네온 그라데이션·사이버 브레인), 실사 인물 얼굴, 워터마크, 브랜드 로고, 뭉개진 한글

## 4. 컬러 시스템

- 배경: **단일 딥 컬러 솔리드** (딥 그린·딥 네이비·버건디·차콜·딥 플럼 등) — cover ledger가 제안한 팔레트를 딥 톤으로 해석
- 텍스트: 크림/아이보리 (배경 대비 4.5:1 이상)
- 악센트: 골드·구리·머스터드 계열 1색
- 배경색·은유는 `cover_metaphor_ledger.py suggest` 결과를 따르고, 인접 출간작과 배경색이 겹치지 않게 한다

## 4b. 타이포그래피 — Pretendard 의무 (기존 표지 컨벤션 승계)

모든 표지 텍스트는 **Pretendard** (`~/Library/Fonts/Pretendard-*.otf`, 전 웨이트 설치됨). 기존 표지 생성기(`ebook-cover-generation/cover_queue.py`)와 동일한 웨이트 매핑:

| 요소 | 웨이트 | 파일 |
|---|---|---|
| 제목 | **Black** (필요 시 ExtraBold) | `Pretendard-Black.otf` |
| 부제·태그라인 | **Bold** | `Pretendard-Bold.otf` |
| 저자·출판사·시리즈 칩 | Medium | `Pretendard-Medium.otf` |

- 제목은 반드시 굵게 — 얇은 제목 금지. 자간은 살짝 좁게(-1~-2%)가 Pretendard Black에 어울림
- PIL 오버레이·코드 컴포지션 시 위 otf 파일을 직접 로드 (AppleSDGothicNeo fallback은 Pretendard 부재 시에만)
- GPT Image 2.0 프롬프트에는 "Pretendard Black 스타일의 아주 두껍고 모던한 한글 산세리프, 자획 균일"로 스타일을 지시하고, 생성 결과의 글꼴 굵기가 빈약하면 텍스트리스 생성 + Pretendard 오버레이로 전환

## 5. 파일 규격 (cover_spec)

- 최종: `cover.jpg` (소문자 확장자), 1500×2220px, JPEG 품질 90+, 7MB 이하
- 생성 원본이 다른 크기면 `scripts/cover_finalize.py`가 리사이즈·크롭·변환을 담당
- EPUB에 표지가 임베드되므로 표지 교체 후 **EPUB 재빌드 필수**

## 6. 생성 엔진 규정

- **정식 경로는 GPT Image 2.0 (Codex 앱의 네이티브 이미지 생성 도구) 단 하나** — 별도 API 키 불필요
- 코드 드로잉(PIL·SVG·matplotlib)은 표지 생성 수단으로 금지. 플랫 벡터 결과물은 §3 입체 렌더 기준 미달 → `cover_quality: baseline` 임시 표지로만 허용
- 생성 후 파일 존재 확인 필수: 이미지 도구가 없는 환경(codex CLI exec 등)은 생성 성공을 환각할 수 있다 — 모델의 답변이 아니라 파일이 진실
- 도구가 없는 환경에서는 `cover_brief.md`를 책 폴더에 남겨 Codex 앱 세션이 한 번에 생성할 수 있게 한다

## 7. 한글 렌더링 주의

- 이미지 생성 모델이 한글을 그릴 때 자획이 뭉개지면: 텍스트 영역을 비워 달라고 지시하고(레이아웃은 유지) 타이포그래피는 후처리(PIL 오버레이)로 얹는 방식으로 전환
- 생성 결과의 한글은 반드시 판독 검증 — 한 글자라도 이상하면 재생성 또는 오버레이 전환
