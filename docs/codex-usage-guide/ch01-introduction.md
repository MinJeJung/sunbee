# 1장. 도입 판단: Codex를 어디에/어떻게 쓰면 이득인가

> Claude Code 비교 포함 — Codex 도입 전 의사결정에 필요한 모든 것

---

## 1절. Codex가 "실무를 끝내는 방식"

### 읽기→수정→실행→검수→PR 흐름으로 이해하기

Codex는 OpenAI가 만든 **터미널 기반 코딩 에이전트**다. 단순한 코드 생성기가 아니라, 실무 개발자의 작업 흐름을 그대로 따라가는 "소프트웨어 엔지니어 동료"로 설계되었다.

### Codex의 5단계 작업 흐름

```
[1] 읽기(Read) → [2] 수정(Edit) → [3] 실행(Execute) → [4] 검수(Verify) → [5] PR 제출
```

#### 1단계: 읽기 (Read)
- 프로젝트 디렉토리의 파일 구조를 파악한다
- 관련 소스 코드, 설정 파일, 문서를 읽는다
- 의존성(package.json, requirements.txt 등)을 확인한다
- 기존 테스트 코드와 CI 설정을 인식한다

#### 2단계: 수정 (Edit)
- 지시에 따라 파일을 생성하거나 수정한다
- 변경 범위를 최소화하며 기존 코드 스타일을 따른다
- 여러 파일에 걸친 일관된 변경을 수행한다
- diff 형태로 변경 사항을 명확히 보여준다

#### 3단계: 실행 (Execute)
- 수정한 코드를 실제로 실행하여 동작을 확인한다
- 테스트 스크립트(lint, unit test 등)를 실행한다
- 빌드 과정을 거쳐 오류를 사전에 감지한다

#### 4단계: 검수 (Verify)
- 실행 결과 로그를 해석한다
- 오류가 발생하면 자동으로 수정→재실행 루프를 수행한다
- 변경 사항의 영향 범위를 분석한다
- 사용자에게 검토를 요청하기 전 자체 검증을 완료한다

#### 5단계: PR 제출
- 변경 요약을 자동 생성한다
- PR 설명 초안을 작성한다
- 커밋 메시지를 관례에 맞게 작성한다
- 리뷰어가 이해하기 쉬운 형태로 정리한다

### Codex가 동작하는 3가지 표면(Surface)

| 표면 | 설명 | 적합한 상황 |
|---|---|---|
| **CLI (터미널)** | `codex` 명령으로 터미널에서 대화형 작업 | 실시간 페어 프로그래밍, 빠른 수정 |
| **IDE 확장** | VS Code 등 에디터 내에서 Codex 사용 | 코드 탐색+수정을 에디터에서 일괄 처리 |
| **Cloud** | ChatGPT 웹에서 대규모 작업을 위임 | 장시간 자율 작업, 병렬 태스크 |

### 핵심 원리: "샌드박스 안에서 안전하게"

Codex는 모든 작업을 **격리된 샌드박스** 안에서 수행한다:
- 파일시스템과 네트워크 접근이 제한된다
- 승인 모드(Approval Mode)로 위험한 명령 실행 전 사용자 확인을 받는다
- Cloud 환경에서는 인터넷 접근이 완전히 차단된 컨테이너에서 실행된다

## 2절. Codex가 잘하는 일/약한 일

### Codex가 잘하는 일 (강점)

#### 1. 대량 파일 편집 (Bulk File Edits)
- 수십~수백 개 파일에 걸친 일관된 변경
- 변수명 변경, import 경로 수정, API 마이그레이션
- 코드 스타일 통일, 린트 규칙 적용

#### 2. 반복 자동화 (Repetitive Automation)
- `codex exec`으로 정해진 작업을 비대화형 실행
- CI/CD 파이프라인에 통합하여 자동 코드 리뷰
- 변경 로그 업데이트, 이슈 정리, PR 설명 생성

#### 3. 실행/검증 루프 (Execute & Verify)
- 코드 작성 → 실행 → 오류 분석 → 수정 → 재실행의 반복
- 테스트 작성 후 통과할 때까지 자동으로 수정
- 빌드 오류를 스스로 진단하고 해결

#### 4. 코드베이스 탐색 및 온보딩
- 대규모 코드베이스의 구조를 빠르게 파악
- "이 함수가 어디서 호출되나요?" 등의 질문에 즉시 답변
- 새 팀원이 코드를 이해하는 데 소요되는 시간 단축

#### 5. 장시간 자율 작업 (Long-Horizon Tasks)
- GPT-5.3-Codex 기준, 25시간 이상 무중단 작업 수행 사례
- 수만 줄의 코드를 스펙에 따라 자율적으로 생성
- 계획→구현→검증→수정 루프를 스스로 반복

#### 6. 멀티 에이전트 협업
- 여러 Codex 에이전트가 병렬로 서로 다른 작업 수행
- `config.toml`에서 역할별 에이전트 구성 가능
- 대규모 리팩토링을 분할하여 동시 처리

### Codex가 약한 일 (한계)

| 한계 영역 | 설명 |
|---|---|
| **GUI 작업** | 브라우저 조작, 데스크톱 앱 제어 등 시각적 인터페이스 작업 불가 |
| **외부 서비스 접근** | Cloud 모드에서 인터넷 차단됨; CLI에서도 제한적 |
| **매우 큰 파일** | 컨텍스트 윈도우 제한으로 수만 줄의 단일 파일 처리 어려움 |
| **도메인 전문 지식** | 의료·법률·금융 등 전문 분야의 미묘한 판단 |
| **디자인 창작** | 시각 디자인 생성, UI/UX 패턴 창의적 제안은 제한적 |
| **실시간 데이터** | 라이브 데이터베이스 조회, 실시간 API 호출에는 별도 설정 필요 |
| **기존 비표준 빌드** | 커스텀 빌드 시스템이나 독자적 도구 체인에서 오류 가능 |

### 판단 기준: "이 작업에 Codex를 쓸까?"

```
질문 1: 작업이 텍스트(코드/문서) 기반인가?  → Yes → 후보
질문 2: 명확한 완료 조건(AC)이 있는가?      → Yes → 적합
질문 3: 실행 후 결과를 자동 검증할 수 있나?  → Yes → 매우 적합
질문 4: 반복 패턴이 있는가?                  → Yes → 자동화 추천
```

## 3절. Claude Code 개요 (동일 과업 관점)

### Claude Code란?

Claude Code는 Anthropic이 만든 **터미널 기반 AI 코딩 에이전트**다. `npm install -g @anthropic-ai/claude-code`로 설치하며, 터미널에서 `claude` 명령으로 실행한다.

### Claude Code의 핵심 특징

#### 터미널 에이전트 구조
- 로컬 터미널에서 직접 실행
- 현재 디렉토리의 파일을 읽고, 수정하고, 명령을 실행
- IDE(VS Code 등)와 통합하여 에디터 내에서도 사용 가능

#### 높은 컨텍스트 인식
- 프로젝트 전체 구조를 깊이 이해
- 여러 파일 간의 관계와 의존성을 파악
- 변경의 영향 범위를 정확히 분석

#### 대화형 워크플로
- "계획 먼저, 실행은 나중" 방식
- 복잡한 작업 전 계획을 제시하고 승인을 받음
- 단계별로 진행 상황을 보고

#### 플러그인/워크플로 구조
- MCP(Model Context Protocol) 서버 통합
- 슬래시 커맨드(`/help`, `/commit` 등)로 빠른 작업
- 훅(hooks) 시스템으로 이벤트 기반 자동화

### Claude Code의 작업 흐름

```
사용자 지시 → 코드베이스 분석 → 계획 수립 → 사용자 승인
→ 파일 수정 → 검증 → 결과 보고
```

### 동일 과업 비교 시나리오

**예시: "로그인 API에 rate limiting 추가"**

| 단계 | Codex | Claude Code |
|---|---|---|
| 코드 읽기 | 관련 파일 자동 탐색 | 관련 파일 자동 탐색 |
| 계획 수립 | 바로 수정 시작 (빠름) | 계획 제시 후 승인 대기 (신중) |
| 구현 | 여러 파일 동시 수정 | 단계적으로 수정 |
| 테스트 | 자동 실행+수정 루프 | 실행 후 결과 보고 |
| PR 생성 | Cloud에서 자동 PR | 사용자가 커밋/PR 지시 |

## 4절. Codex vs Claude Code 비교

### 커뮤니티 관찰 포함 종합 비교

#### 설계 철학

| 항목 | Codex | Claude Code |
|---|---|---|
| **철학** | "빠르게 움직이고 반복하라" | "두 번 재고, 한 번 자르라" |
| **접근 방식** | 자율적 실행, 병렬 작업 | 대화형, 로컬 페어 프로그래밍 |
| **소스 코드** | 오픈소스 (GitHub 59k+ 스타) | 클로즈드 소스 |

#### 아키텍처 비교

| 항목 | Codex | Claude Code |
|---|---|---|
| **실행 환경** | 로컬 CLI + Cloud 샌드박스 | 로컬 터미널 전용 |
| **격리** | Cloud: 완전 격리 컨테이너 | 로컬에서 직접 실행 |
| **언어/런타임** | Rust (네이티브 바이너리) | Node.js 기반 |
| **멀티 에이전트** | 지원 (config.toml 설정) | 단일 에이전트 |

#### 성능·비용 비교

| 항목 | Codex | Claude Code |
|---|---|---|
| **속도** | 동일 작업에 ~3배 적은 토큰 사용 | 더 정확하지만 상대적으로 느림 |
| **비용** | 무료~$20/월 (Plus 기준) 또는 API 종량제 | Anthropic 구독 또는 API 종량제 |
| **Rate Limit** | 상대적으로 관대 | 상대적으로 제한적 |

#### 강점 비교

| 능력 | Codex 우위 | Claude Code 우위 |
|---|---|---|
| **벤치마크** | 토큰 효율성 | SWE-bench 정확도 (23%p+ 차이) |
| **복잡한 리팩토링** | | 다중 파일 리팩토링에서 더 정확 |
| **빠른 프로토타이핑** | 빠른 스캐폴딩, 유틸리티 작성 | |
| **장시간 작업** | Cloud에서 자율 실행 | |
| **코드 품질** | | 프로덕션 수준의 신중한 코드 |
| **모호한 요구사항** | | 요구사항 해석에 강함 |

#### 언제 어떤 것을 쓸까?

**Codex를 선택할 때:**
- 빠르고 잘 정의된 작업 (스캐폴딩, 유틸리티 함수 작성)
- 단순한 버그 수정
- 대량 반복 변경
- 병렬 작업이 필요한 경우
- CI/CD 자동화에 통합할 때

**Claude Code를 선택할 때:**
- 복잡하거나 높은 수준의 프로젝트
- 다중 파일 리팩토링
- 모호한 요구사항 해석이 필요한 경우
- 프로덕션 코드의 정확성이 중요한 경우
- 깊은 코드베이스 이해가 필요한 경우

#### 커뮤니티 합의: "둘 다 쓰는 것이 최선"

> "Codex vs Claude Code는 잘못된 이분법이다. 시장은 두 가지 상호작용 철학으로 갈라졌다: 페어 프로그래밍하는 대화형 로컬 코파일럿과, 업무를 위임하는 자율형 클라우드 에이전트. 가장 진보된 개발 워크플로는 멀티 에이전트 방식 — 두 도구를 전략적으로 함께 사용하는 것이다."
> — 커뮤니티 종합 평가

## 5절. 도입 체크리스트

### 계정/권한/보안/검수(SOP)/교육 범위

#### 1. 계정 및 라이선스

| 체크 항목 | 설명 | 확인 |
|---|---|---|
| OpenAI 계정 보유 | ChatGPT Plus/Pro/Business/Enterprise 중 하나 | [ ] |
| 또는 API 키 보유 | OpenAI API 키 발급 및 크레딧 확보 | [ ] |
| 팀 라이선스 결정 | 개인 계정 vs 팀/조직 계정 선택 | [ ] |
| 비용 예산 수립 | 월간 예상 사용량 기반 비용 산정 | [ ] |

#### 2. 권한 및 접근

| 체크 항목 | 설명 | 확인 |
|---|---|---|
| 개발 환경 접근 | 작업 대상 리포지토리 접근 권한 확인 | [ ] |
| GitHub 연동 설정 | Codex GitHub Action 또는 @codex 멘션 설정 | [ ] |
| 승인 정책 결정 | 자동 승인 범위 및 수동 검토 기준 설정 | [ ] |
| 역할별 권한 분리 | 팀원별 Codex 사용 범위 결정 | [ ] |

#### 3. 보안

| 체크 항목 | 설명 | 확인 |
|---|---|---|
| 민감 데이터 정책 | .env, 자격증명 파일 등의 Codex 접근 차단 | [ ] |
| 샌드박스 모드 결정 | read-only / workspace-write / full-access 선택 | [ ] |
| 코드 유출 위험 평가 | Cloud 사용 시 코드가 OpenAI 서버로 전송됨을 인지 | [ ] |
| 네트워크 정책 | 회사 방화벽/VPN 환경에서 접근 가능 여부 확인 | [ ] |

#### 4. 검수(SOP) 프로세스

| 체크 항목 | 설명 | 확인 |
|---|---|---|
| 리뷰 프로세스 수립 | Codex 생성 코드의 필수 리뷰 정책 | [ ] |
| 테스트 기준 설정 | Codex 작업 후 실행할 테스트 범위 | [ ] |
| 변경 추적 방법 | Codex 변경분을 구분하여 추적하는 방법 | [ ] |
| 롤백 절차 | Codex 작업 결과에 문제 시 되돌리기 절차 | [ ] |

#### 5. 교육 범위 (비개발자 기준)

| 대상 | 교육 내용 | 예상 시간 |
|---|---|---|
| **기획자/PM** | Git 기초(16절) + 지시문 작성(11절) + PRD 활용(21~25절) | 4시간 |
| **디자이너** | 파일 구조 이해 + 리소스 관리 + PR 확인법 | 2시간 |
| **QA** | 테스트 자동화 + 결과 검증 + 이슈 등록 | 3시간 |
| **관리자/리더** | 도입 효과 이해 + 비용 관리 + 보안 정책 | 1시간 |

#### 도입 단계별 로드맵

```
Phase 1 (1주): 설치 + 인증 + 첫 성공 경험 (10절)
Phase 2 (2주): 지시문 템플릿 학습 + 개인 작업 적용
Phase 3 (4주): Git/PR 워크플로 통합 + 팀 SOP 수립
Phase 4 (계속): 자동화 확대 + 멀티 에이전트 도입
```
